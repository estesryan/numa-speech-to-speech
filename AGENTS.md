# Agent instructions

Guidance for AI coding agents working on Numa. Read these first:

- [README.md](README.md): setup and how to run Numa.
- [TESTING.md](TESTING.md): which checks to run.
- [docs/architecture.md](docs/architecture.md): how the pieces fit together.
- [frontend/AGENTS.md](frontend/AGENTS.md): notes for this Next.js version (generated by Next.js).

## Conventions

- **Frontend:**
  - npm only (`package-lock.json`); never pnpm or yarn.
  - TypeScript strict, Biome for formatting and linting, and Zod for untrusted data.
  - Tests use Vitest and Testing Library.
- **Voice engine:**
  - uv and Python 3.12; dependencies are pinned in `uv.lock`, speech-to-speech at 1.1.0.
  - Never edit files inside `.venv`. Changes to upstream behaviour belong in `numa_voice/patches/`, guarded with
    `require` / `require_source`, with a test.
- **Terminology:** Numa, assistant, user, conversation.
  - Some internal and protocol names still say `host` (the persona field, the transcript speaker id, error types)
    and the prompts call the user "the guest".
  - Keep those as they are unless the task is to change them.

## Boundaries

- **Prompts:**
  - Persona prompts live only in `backend/voice-engine/personas/`.
  - The engine instructions and the interruption note text are in `numa_voice/interruption.py`, mirrored in
    `frontend/lib/realtime/interruption.ts` and the shared event traces. Keep all three in step.
  - Wording changes alter model behaviour and need a live check by a person.
- **Security and consent:**
  - Do not widen the engine's network exposure (it listens on `127.0.0.1` behind an Origin allowlist).
  - Do not let clients send prompt text or choose voices.
  - Do not bypass Voice Studio's consent requirement or the rule that personas cannot use saved voices.
- **Models:**
  - Never modify, move or delete anything in `models/`.
  - Do not download models or change `model-manifest.yaml` unless asked; downloads are several gigabytes.
- **User data:**
  - `data/voices/` holds private voice recordings. Never read, modify or delete it.
  - Tests must use a temporary directory (`NUMA_VOICES_DIR`).
  - Before running integration or browser tests, check whether an engine is already running on port 8765. It may
    hold the user's real data: ask before stopping it, and do not point tests that write voices at it.
- **Secrets:** never commit model weights, recordings, `.env` files or generated configs. `.gitignore` covers them;
  keep it that way.

## Making changes

- Keep changes focused: no unrelated refactors, dependency upgrades or new features.
- Update tests and the relevant document when behaviour changes. Describe only what is implemented.
- Run the quick checks from [TESTING.md](TESTING.md) for the parts you touched. Live-model and browser tests are
  slow; run them only when the change needs them.
